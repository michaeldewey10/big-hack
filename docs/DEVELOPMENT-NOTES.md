# Historical development notes

These notes retain the implementation history and its validation limits. Some sections describe earlier UI revisions. See the root README for current usage and build instructions.

# Big Hack

A native Rust application built with Zed's [GPUI 0.2.2](https://github.com/zed-industries/zed/tree/main/crates/gpui). Its pale background, serif text, rough marker underlines for selected controls and text-button hover, with a distinct accent for each tab (You red, Party blue, Items yellow, Camera green, Places orange, Big Fun purple), vertical divider, and outlined circle sliders take their visual direction from Big Walk's settings screen.

## Run

For another Windows x64 computer, share the standalone **outputs/BigHack.exe**. It contains the UI, bridge, Visual C++ runtime, documentation, and license files. Double-click it to extract a unique runtime folder under `%LOCALAPPDATA%\BigHack\runtime` and open the app. Python, Rust, and a separate bridge download are not required. The launcher waits for the app to close, then removes that launch's extracted files; a forced shutdown or a locked file can leave the folder behind. Logs and settings stay in their usual BigHack folder. No installer or administrator access is required for extraction.

The folder/ZIP package is also available: open **BigHack.exe** inside **Big-Hack** and keep its accompanying files together. Both packages use the same UI and bridge. The matching supported Big Walk build must be installed and running on the destination computer.

The executable, window, and taskbar use a red adaptation of Big Walk's original icon. All artwork, including the eye and pupil, uses shades of red. Windows icon sizes from 16 to 256 pixels are embedded through `build.rs` and `assets/icon.rc`.

Big Hack immediately looks for **Big Walk.exe**, verifies the supported game build, and attaches automatically. If the game is not running, it waits for the next launch. Enter a game session for character and item data to appear. It reattaches after the game restarts. If more than one matching process is running, it asks you to close the extra client rather than picking one silently.

- **You**: Movement speed, Jump height, combined Throw / kick strength, and Throw charge speed sliders, plus Landing dizziness On / Off. Sliders snap to 0.25× steps; Jump height and Throw / kick strength range from 0.25× to 99×, while Movement speed and Throw charge speed remain 0.25× to 20×. Release to apply and Escape to cancel a drag. The combined strength slider scales normal throws, low throws, and kicks together, preserving their original ratios. Charge speed reduces the original wind-up duration by the selected factor, retaining a positive duration. **Restore original** returns tuning and the landing setting to their captured baseline. The scrollable page also has presets, held-item press-and-hold Use / Drop, pocket contents, and head/torso/leg palette selectors.
- **Party**: a plain list of players, their distances, and your current selection's state, carried object/player, and coordinates. Select a remote player for Pick up or Teleport to.
- **Items**: a searchable list of client-loaded item instances, ordered by distance. Select an item to see its holder, coordinates, and Pick up / Teleport to actions.
- **Selective collection**: Items offers collection of the selected type, with a 20 m / 100 m / any-distance selector. It reuses the existing collection sequence, progress and Stop control, operating on eligible loaded item identities captured when clicked.
- **Big Fun**: Spawn 10 corpses around you, Spawn 10 corpse bowling pins, Clear all corpses, Grab every item, Bring everyone to you, and Randomize my colors. Randomize my colors picks an ordinary palette color independently for your head, torso and legs, avoiding each current color when alternatives exist. It uses the same host-only appearance path and observed-state confirmation as the You page. Collection, corpse and party actions each start one bounded sequence. Corpses require the running host/server and an actual registered Corpse prefab; new corpses are placed on a three-metre ring and marked outside prop saving. Appearance is copied from your character through the native color setters, with a unique body identifier. This creates fresh bodies without transferring your held item or pocket contents. The fireworks and flare actions have been removed.
- **Reconnect** resumes automatic process discovery. Connection changes and action results are recorded in the local diagnostic log.
- **Camera**: a line-and-circle zoom slider from 0.25× to 8× in 0.25× steps, applied once on release (Escape cancels), Detach camera / Return camera, directional movement in 0.25 / 1 / 5 / 20 metre steps, and independent 15-degree look controls. Photo mode moves the actual local camera without teleporting your character. The world continues running. Return camera restores hierarchy and view orientation while keeping your chosen zoom; normal app detach also restores original zoom. Teleporting or saving a character spot while the camera is detached is refused until you return the camera.
- **Places**: Teleport back, Save this spot, and saved spot selection / teleport / delete. Back remembers the position and rotation before the last app teleport for the current owned character. Saved spots include the audited game build and are disabled for a different build. Places is a text list; the map remains removed.

Presets and saved spots are stored in `%LOCALAPPDATA%\BigHack\library.json`. Presets capture all four multipliers plus the landing toggle, use baseline-relative writes, and roll back if any part fails. Equipment on You has only Backpack and Holster. When a slot is empty, **Equip closest** finds the nearest unused, compatible client-loaded gear, picks it up and wears it through normal game actions. Hands must be empty. Gear held by anyone, pinned to another home, worn, or in inventory is excluded. Distance and eligibility are recalculated on the owned character update when clicked. Once gear is worn, **Store held item** appears while you hold an item and selects a compatible empty storage home; **Take off** remains available with empty hands, and occupied storage shows **Take out <item>**. Blindfold and empty storage rows have been removed. Appearance reads the actual palette and changes your own head, torso and legs when you are hosting, through the game's `ServerSetLook` path used by dye interactions. The client `CmdChangeLook` receiver is empty in the supported build, so appearance editing is disabled on a non-host client with a reason shown. New selections use ordinary palette colors; an existing worn reward color can stay unchanged. These appearance changes follow the game's normal persistence behavior and are not reverted by Restore original. Use is a single press-and-hold control: mouse-down presses, mouse-up releases even outside the button. Focus loss, Escape and page changes also request release. Quick clicks queue release even before the press response. Owner/generation/hold IDs fence heartbeats and releases; a 1.5-second bridge lease requests a main-thread release if input heartbeats stop. Normal app detach also attempts release. Other actions wait while the app is holding Use.

The You menu ends with **Restore original**, without explanatory text below it. Successful actions are recorded only in the diagnostic log; action errors still appear in the UI.

Player samples target **5 Hz**; item membership/positions target **1 Hz**. Rows keep stable identities across refreshes. Actions are disabled when the connection is stale or another action is pending. Pickup also requires empty hands and an unheld item. Each click schedules one action on your locally owned character's Unity update. Teleport uses the target's fresh position, placing you 1.5 units beside and 1 unit above it while preserving your orientation.

**Ctrl+1/2/3/4/5/6** switches between You, Party, Items, Camera, Places, and Big Fun. Search is available only in Items: **Ctrl+F** focuses it, **Esc** clears it, and **Ctrl+V** pastes into it. Party always shows the full roster.

**Grab every item** captures the currently listed, unheld, non-inventory props when clicked and brings them near you one at a time. It cannot reach objects that are not loaded on this client. It rechecks each item's identity and the game's IsSafeToPickUp rule, uses ActionPickUpProp for normal prediction/action numbering, and waits for both network-held state and local hands/holder state. After a 200 ms hold, it releases through CmdPickUp with HeldType.Nothing, explicit nearby drop data, and zero wind-up. This keeps the drop separate from your throw-strength multiplier. Items are spread within roughly five metres of you.

The running sequence shows processed/total, collected, skipped and failed counts. **Stop** finishes releasing the current item and then stops before picking up another. Held, inventory, unloaded or blocked props are skipped; pickup refusals are counted, and an unexpected held item or unresolved release stops the run. Each captured identity is attempted once. The duration limit scales to four seconds per selected item plus a small completion allowance, up to 4,096 items. Normal detach allows up to six seconds to finish the current pickup/release and restore your settings. The new collection action has been implemented from recovered native paths and has not been run in-game during this update.

Bring everyone uses your own existing pickup/drop commands, one party member at a time, rather than editing remote character transforms. It requires free hands and a free-standing character. Each target must also stand freely with empty hands; the native PoseIsSafe check is retained. The bridge waits for the exact target to occupy your carry pose, holds for at least 750 ms across updates, then requests drop and observes release before proceeding. It stops on refusal, changed identity, disconnection, an occupied pose, or timeout and reports the completed count. Up to 12 targets are supported per sequence, with a 44-second deadline. Normal detach attempts to release only the member currently carried by this sequence. Actual remote arrival and host acceptance require in-game observation; no party-moving action was executed during this update.

Character tuning writes run on your owned character's update and are refused if another live character shares the same tuning object. Changes multiply the captured original values, so repeated clicks do not compound. Movement speed applies one multiplier to all seven normal/sprint movement fields while preserving their original ratios. Jump height scales launch velocity and its upward cap by the square root of the selected multiplier; actual height depends on game physics and collisions. Throw / kick strength multiplies the maximum force of both normal and low throws and kicks. The same strength multiplier also scales kickSettings.maxForce, and Throw charge speed divides maxWindUpDuration by the selected multiplier; torque and launch curves remain unchanged. The selected value is a force multiplier, not a guaranteed distance or velocity.

Landing dizziness **Off** sets the local PlayerFaller.ignoreFalling flag. The recovered update skips the automatic fall reaction, including dizziness, forced sitting, and dropping held items. An already active daze is allowed to expire normally. Turning it back On calls ClearNextFall to discard the stale fall-height baseline before enabling reactions again. The original flag is captured separately for each owned landing controller. The bridge attempts to restore changed tuning fields and the landing flag on normal disconnect or app closure while the same character is available. Use Restore original before closing if you need an explicit restoration result. Throw, kick, charge, and landing controls still require live gameplay observation; no throw, kick, charge, or fall action was executed during this update.

`BigHack.exe --preview` opens labelled sample data with game actions disabled. **Connect to game** leaves preview mode and starts normal discovery. `--preview --items` starts on the item page; `--preview --fun` starts on Big Fun. `--fun` also works during live scanning. The Map page and map-click teleport commands have been removed. Normal double-click startup uses live scanning.

## Build

Requires a Windows MSVC Rust toolchain and Visual Studio C++ Build Tools. The Rust UI pins GPUI to 0.2.2, with transitive versions recorded in Cargo.lock.

```powershell
cargo build --release
cargo test --release
```

The portable package also bundles the existing Frida instrumentation as a separate local bridge executable. To build both parts, use `build.ps1` from this folder. It uses the workspace's existing PyInstaller/Frida dependencies, or the Python environment and `BIG_HACK_FRIDA_PATH` you supply. On a new machine, install `pyinstaller==6.22.3` in that Python environment and `frida==17.23.3` into `bridge/vendor` (or set BIG_HACK_FRIDA_PATH to its directory).

`BIG_HACK_PYTHON` can override the Python executable for development runs without the bundled bridge. The release package uses the adjacent bridge executable.

After building the portable folder, run `packaging/build-single.ps1` to produce `outputs/BigHack.exe`. The script embeds the existing portable files and an x64 `vcruntime140.dll` from the Visual Studio redistributable folder, with the red app icon. It compiles a small Rust launcher with a static CRT, forwards command-line arguments (including `--preview`), and requires no downloads at runtime. `-RuntimeDll` can select the redistributable DLL explicitly. Rebuild this standalone package whenever the UI or bridge changes.

## Crash fix and diagnostics

The Windows text-layout crash was reproduced and traced to GPUI's ellipsis handling of UTF-8 text runs. Big Hack now clips overflowing labels without shortening the text runs. See `CRASH-INVESTIGATION.md` for the evidence and isolated regression test. Panic logs are written to `%LOCALAPPDATA%\BigHack\logs\BigHack-<pid>.log`.


Existing presets with separate kick values are read compatibly: their saved throw multiplier now drives the combined throw/kick control; the old independent kick value is ignored. New presets store the four current controls. Restore original restores all three original launch forces.

The former 100× controls now stop at 99×; saved presets are clamped on load/apply. The equip/storage and hold-button changes were compiled and packaged, with no new gameplay action or test suite run during implementation. Equipment operations report completion only after the corresponding synchronized state is observed; a three-second deadline reports an unconfirmed result if it does not settle. See bridge/POCKET-TOOLS.md for recovered paths and scope.

Appearance arrows use fixed 36 by 38 pixel press targets. Each press requests one palette step. The bridge waits up to three seconds for the synchronized head, torso and leg IDs to match across subsequent updates; an unconfirmed change shows an error. Arrow dispatch and completion are recorded in the local log. This revision compiled and passed syntax parsing; appearance changes have not been exercised in-game during this update.

Appearance handler correction: passive inspection confirmed `UserCode_CmdChangeLook__Int32__LookPart` at RVA 0x2da6b0 begins with `c2 00 00` (RET 0), matching the recovered body. `ServerSetLook` at RVA 0x39a9a0 updates synchronized look fields, invokes their hooks, and saves/puffs when saveChange is true. The bridge now calls it only for changed parts of the host's own character, after checking the real NetworkIdentity.isServer and NetworkServer.active values. Client controls remain unavailable. The existing three-second observed-state confirmation remains. No appearance command was executed during this correction; live color/peer-visible behavior remains for user observation.

## Scrollbars

You, Party, Items, Camera, Places and Big Fun show a vertical scrollbar when their content overflows. Each uses the tab accent color, with a thumb proportional to the visible content. Drag the thumb, click the track to jump, or scroll with the mouse wheel over either the content or its scrollbar. Each tab retains its own scroll position. The item list retains virtual rendering for large item counts. Release, focus loss, Escape and page changes end a scrollbar drag. This update was compiled; scrollbar interaction and layout have not been visually tested during implementation.

## Corpse bowling pins

The second Big Fun button, immediately below Spawn 10 corpses around you, spawns ten registered corpse instances in a 1 / 2 / 3 / 4 triangular rack. The first body is four metres ahead of your captured position, with one-metre nearest-neighbour spacing and rows extending away from you. Direction comes from your validated owned camera, projected onto the horizontal plane; a vertical view uses camera right to recover the heading. Return a detached camera before using it. Positions and heading are captured once before any spawn, and all ten destinations are checked before the sequence begins. Bodies initially face toward you and start at the same vertical offset as the existing corpse-ring action (one metre above character position); normal physics then applies. This does not sample terrain or hold bodies upright, so use flat open ground for a recognizable rack.

This reuses the host-only registered prefab, unique identifiers, native appearance setters, non-saveable bodies, fixed ten-instance count and one-at-a-time spawn sequence. The existing ring button retains its layout. Compilation and bridge syntax parsing were performed; the bowling spawn has not been triggered during implementation.

## Clear all corpses

The host-only Clear all corpses button sits below the two corpse spawn buttons. It captures every active, network-spawned Corpse currently in the host's Corpse.allCorpses registry (up to the supported list limit of 4,096), including ordinary game corpses and previous Big Hack spawns. It excludes prefab assets and live PlayerCharacter objects. Each captured body is revalidated by component pointer, network identity, net ID and corpse identifier before cleanup; corpses appearing after the click belong to a later clear.

The sequence calls the normal Corpse.ServerEmptyAllPockets routine and waits for the four gear/held-item homes to empty. A body whose contents do not release is retained and counted as a failure. Prop.PrepareForDestroy handles the ordinary held-body cleanup before Mirror.NetworkServer.Destroy removes its network root. Completion requires that the corpse no longer appears in the active corpse list and its net ID is absent from NetworkServer.spawned. The UI shows cleared / skipped / failed counts and Stop. The runtime, bridge and UI deadlines scale to 4N+5 / 4N+8 / 4N+12 seconds for the N captured corpses.

Recovered Corpse.ExpireDueToRevival calls ServerEmptyAllPockets (RVA 0x46ef30) and Prop.PrepareForDestroy (RVA 0x3c5330). The clear action uses those cleanup methods directly, avoiding the revival routine's transfer of backpack/holster equipment to a live player. A passive read on 2026-10-17 found 100 active corpses, matching host-side corpse/prop network identities and all four expected homes in three sampled bodies, with both cleanup method RVAs matching recovery. No cleanup method or clear command was executed during implementation. Native removal, item release and peer-visible cleanup still require live observation.
